# План модернизации и улучшения расширения vscode-sftp

Этот документ содержит анализ текущего состояния расширения `vscode-sftp`, его сильные и слабые стороны, а также масштабный план по его улучшению с оглядкой на эталонный функционал IDE от JetBrains (в частности, PhpStorm).

## 1. Сильные стороны текущего расширения (Что уже хорошо)

- **Популярность и база:** Это самый известный форк оригинального проекта `liximomo`. У него есть солидная кодовая база и сформированная архитектура.
- **Поддержка протоколов:** Хорошая базовая поддержка FTP, FTPS, SFTP.
- **Продвинутая конфигурация:** Поддержка нескольких профилей в одном проекте, file watcher (отслеживание изменений), connection hopping (подключение через промежуточные серверы).
- **Базовый Remote Explorer:** Присутствует базовая панель для просмотра файлов на сервере.
- **Upload on Save:** Удобная функция автоматической выгрузки файла при нажатии `Ctrl+S`.

## 2. Слабые стороны и критические проблемы

- **Слепая синхронизация:** Зачастую расширение пытается загрузить/скачать всё подряд, вместо того чтобы проверять, какие файлы действительно изменились (по дате модификации, размеру или хэшу).
- **Слабая отказоустойчивость:** При массовой выгрузке/загрузке сотен файлов часто вылетают ошибки обрыва соединения (timeout, disconnect). Очередь не умеет нормально восстанавливаться после таких сбоев.
- **"Скромный" Remote Explorer:** Текущий проводник на сервере слишком примитивен. В нем не хватает Drag & Drop, изменения прав доступа (CHMOD), продвинутого поиска и удобной навигации.
- **Невидимая работа (UX/Очередь):** Пользователь не видит наглядную очередь с оставшимися файлами. Значки внизу экрана малоинформативны, нельзя отменить конкретный файл или посмотреть детальный статус.
- **Конфигурация только через JSON:** Нет визуального редактора настроек подключения (как окно Deployment в PhpStorm), что повышает порог входа.
- **Отсутствие локализации:** Интерфейс, лог и ошибки исключительно на английском языке.

## 3. Сравнение с эталоном (PhpStorm) — Чего не хватает?

В PhpStorm функционал работы с сервером (Deployment) вылизан годами. Основные фишки, которых остро не хватает в `vscode-sftp`:

1. **Sync with Local / Sync with Deployed:** Окно диффа (разницы), где наглядно показано: какие файлы есть только на локалке, какие только на сервере, а какие отличаются. Пользователь может выбрать галочками, что именно синхронизировать.
2. **Transfer Queue (Очередь передачи):** Полноценное окно (Tool Window), где списком идут файлы: сколько передано, скорость, сколько осталось, какие файлы выдали ошибку.
3. **Keep-Alive & Automatic Reconnect:** PhpStorm виртуозно держит соединение или незаметно переподключается, не прерывая общую задачу загрузки.
4. **Browse Remote Host:** Отдельное мощное окно проводника с возможностью синхронизации конкретной папки в два клика, сравнения папок и редактирования файлов прямо на сервере.
5. **Partial Upload:** Умная проверка временных меток (timestamps) и размеров файлов для загрузки **только недостающих или измененных** файлов.

## 4. Глобальный план улучшений и новых функций

### 🟢 ЭТАП 1: Глобальная переработка Системы Синхронизации (Smart Sync)

- **Умная загрузка (Дельта-синхронизация):** Добавить алгоритм, который перед массированной загрузкой скачивает список файлов с сервера (с датами и размерами) и сравнивает с локальной копией. Загружать/скачивать **только те файлы, которые отличаются**.
- **Предварительный просмотр синхронизации:** Перед выполнением команды `Sync` выводить интерфейс (например, через Webview Provider), показывающий таблицу: `<Локальный файл> | <Статус (Новый/Изменен/Удален)> | <Серверный файл>`. Пользователь может отметить нужные файлы галочками и нажать "Run".
- **Защита от перезаписи свежих файлов:** Выдавать предупреждение, если файл на сервере новее, чем локальный (чтобы случайно не затереть чужие изменения).

### 🟢 ЭТАП 2: Улучшение визуальной части и Очереди (UI/UX)

- **Окно "Transfer Queue" (Очередь передачи):** Создать новую панель (вкладку внизу, где Terminal/Output), которая покажет:
  - Прогресс-бар текущей сессии синхронизации.
  - Скорость передачи (КБ/с, МБ/с).
  - Таблицу файлов в очереди (ожидают, загружаются, завершены, ошибка).
  - Кнопки управления: "Отменить всё", "Пропустить текущий", "Повторить ошибки".
- **Визуальный редактор настроек:** Вместо ручного написания `sftp.json` создать красивую HTML/React форму (через VS Code Webview) для добавления и тестирования серверов с кнопкой "Test Connection".

### 🟢 ЭТАП 3: Прокачка Remote Explorer (Проводника на сервере)

- **Богатый контекстное меню:** Добавить команды: `Сравнить с локальным`, `Загрузить сюда`, `Скачать выбранное`, `Изменить права доступа (chmod)`, `Копировать путь к файлу`.
- **Drag & Drop:** Поддержка перетаскивания файлов с локального рабочего стола или локального эксплорера прямо в дерево удаленного сервера.
- **Поиск на сервере:** Добавить кнопку поиска (возможно, работающую через ssh `find` для экономии времени, если протокол SFTP).
- **Синхронизация по клику:** Возможность кликнуть правой кнопкой на папку в Remote Explorer и выбрать `Sync from local`.

### 🟢 ЭТАП 4: Стабильность и Ядро

- **Pool of Connections (Пул соединений):** Сейчас одновременная загрузка 100 файлов может привести к "Too many connections" и бану IP-адреса. Нужно сделать настраиваемый лимит (например, макс. 4 одновременных загрузки).
- **Авто-рестарт при обрыве:** Если во время выгрузки произошел "Socket hang up" или обрыв связи, расширение должно не падать с ошибкой, а подождать 3 секунды, переподключиться и продолжить выгрузку с **того же места**.
- **Обработка символических ссылок (Symlinks):** Корректная работа с симлинками (сейчас с ними часто бывают проблемы при скачивании).

### 🟢 ЭТАП 5: Локализация (Русификация)

- Подключить библиотеку `vscode-nls` (Native Language Support), которая является стандартом для локализации расширений VS Code.
- Вынести все хардкодные английские строки (команды, уведомления, ошибки) в `package.nls.json`.
- Создать файл `package.nls.ru.json` и перевести всё расширение (команды палитры, настройки, сообщения в интерфейсе) на русский язык.

## 5. С чего начать разработку? (Первые шаги)

1. **Изучить ядро (src/core/ и src/transfer/):** Понять, как сейчас устроена очередь (Pool/Queue). Ограничить количество одновременных `Promise` при передаче файлов.
2. **Улучшить логику 'Sync':** Найти код, отвечающий за команды `local -> remote` и `remote -> local` и встроить туда сравнение по времени изменения файла (`mtime`) и размеру.
3. **Локализация:** Вынести базовые команды пакета в `package.nls.json` и начать делать русский перевод, чтобы было приятнее работать.
4. **UI Очереди:** Создать новый `WebviewPanel` или интегрировать кастомные TreeView для отображения активных загрузок, скорости и оставшихся файлов.
